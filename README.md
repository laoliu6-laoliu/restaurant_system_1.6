# 臻味餐厅管理系统 v1.6

Spring Boot 2.7 / Java 11+ / Vue 3 / MySQL。原始源码保存在 Git 标签 `v0.1`，当前版本为 `v1.6`（软件版本号 `1.6.0`）。

## 启动与访问

本机数据库已升级，直接运行 `./start-project.ps1`。它在后台启动后端和前端，日志位于 `.runtime/`。

- 系统页面：http://127.0.0.1:5174
- 后端接口：http://127.0.0.1:8082/api
- 项目不使用 8081。前端固定使用 5174，端口占用时明确报错。

也可以分别在终端启动：

```powershell
cd backend
mvn spring-boot:run
```

```powershell
cd vue3-frontend
npm ci
npm run dev -- --host 127.0.0.1
```

测试账号：管理员 `A0001`、员工 `E0001`、顾客 `C0001`；密码均为 `123456`。选择对应身份后登录。

## v1.6 功能

- 顾客端新增独立的“我的预约”菜单，集中查看当前账号已经预约的餐桌信息。
- 当前预约卡片展示餐桌编号、座位数、实时桌况、预约时段、到店截止时间、人数、联系电话、预约来源、预约编号和押金状态。
- 已结账、已取消和未到店预约归入历史预约列表；预约信息与餐桌实时状态每 5 秒自动刷新，也可手动刷新。

## v1.5 功能

- 员工和管理员可结束进行中的订单，系统记录结束时间，并在没有其他进行中订单时把餐桌转为待清理。
- 已结束订单不再允许换桌或继续支付，订单列表会显示“进行中/已结束”状态与结束时间。
- 员工和管理员可永久删除已结束订单；进行中的订单不能直接删除。
- 删除已结束的待支付订单会恢复菜品库存；删除已支付订单会清除订单明细和支付关联，不回补已售库存。

## v1.4 功能

- 员工可为待支付和已支付订单办理换桌，订单支付后仍会显示“换桌”操作。
- 换桌继续按订单日期和当日三位编号定位订单，并保留原有的人数、原桌状态、目标桌空闲状态和座位容量校验。
- 已支付订单换桌后保持已支付状态和原支付结果，新桌转为使用中，原桌转为待清理。

## v1.3 功能

- 员工餐桌管理中的预约状态按当天计算；只有未来日期存在预约、今天没有预约的餐桌显示为空闲。
- 今天存在有效预约的餐桌显示“已被预订”，并逐条展示预约起止时间。
- 使用中和待清理继续反映餐厅现场状态；若该桌今天还有预约，预约时间仍会同时显示。
- 后端每次读取餐桌时自动按上海时区校正当天预约状态，跨日后无需人工重置。

## v1.2 功能

- 预约改为按餐桌、日期和两小时时段判断冲突，同一餐桌可以预约不同日期，也可以预约同一天内互不重叠的时段。
- 顾客可从任意实时状态的餐桌进入预约表单；系统会把已被占用的线上预约时段标记为“已被预约”并禁止重复选择。
- 顾客餐桌状态页新增电话咨询提醒，建议预约前亲自致电餐厅确认用餐人数和时段。
- 员工登记电话预约时也可选择已有其他日期预约的餐桌，最终由服务端统一防止时间重叠。

## v1.1 功能

- 员工可在预约管理中对已到预约时间但顾客未到店的记录执行“取消订单且不退回押金”。
- 操作确认框会显示不予退还的押金金额；确认后预约状态显示为“订单已取消（押金不退）”，并立即释放餐桌。
- 正常取消入口明确标记为“正常取消并退押金”，便于员工区分两种处理方式。

## v1.0 功能

- 顾客超过到店截止时间仍未到店时，系统自动将预约标记为“未到店已取消”。
- 未到店取消会把已支付押金标记为“已扣除”，不执行退款，并立即释放预约餐桌。
- 预约时间开始后，员工可以在预约管理中点击“未到店取消”提前确认；系统会明确提示押金不予退回。
- 正常取消仍走原有退款流程，避免把普通取消误判为未到店。

## v0.9 功能

- 员工端“电话预约”升级为“预约管理”，统一显示顾客线上预约和员工登记的电话预约。
- 每条预约明确标记预约来源，并直接展示预约时间、餐桌编号、顾客、人数、押金和当前状态；线上预约完成支付后会自动出现在员工端。
- 管理员“订单明细”查询改为订单级列表，每个订单只显示一行订单编号，不再把每道菜拆成独立记录。
- 管理员点击“订单详情”后按需加载该订单所点菜品、数量、金额和备注。

## v0.8 功能

- 餐桌增加至 15 张，2、4、6、8、12 人桌各 3 张；新增的 12 人桌编号为 `T0013`–`T0015`。
- 12 人桌预约押金为 ¥70，继续沿用每增加 2 个座位加收 ¥10 的规则。
- 菜品增加至 24 道，新增蜜汁烤鸭胸、香草羊排、松露奶油宽面、日式照烧鳗鱼饭、泰式冬阴功汤、玉米奶油浓汤、牛油果鲜虾沙拉、脆皮春卷、提拉米苏、熔岩巧克力蛋糕、百香果气泡水和抹茶拿铁。
- 24 道菜均使用本地图片，可在顾客菜单、员工菜单和管理员菜品管理中显示。

## v0.7 功能

- 顾客“餐桌状态”页面显示空闲、使用中、待清理和已预订四种状态，每 5 秒自动刷新，也可手动刷新。
- 顾客可选择空闲餐桌、预约日期和 2 小时时段，并填写用餐人数；支持 11:00、13:30、17:00、19:30 四个时段。
- 系统按餐桌容量计算押金。顾客完成微信或支付宝模拟押金支付后，餐桌立即变为“已预订”，预约仅对当前顾客账号可见。
- 预约开始后有 30 分钟到店宽限。员工及时接待并开单后，顾客完成账单支付时押金按原支付方式模拟退回。
- 到店截止时间后仍未接待开单的预约会自动变为“超时未到店”，押金标记为“已扣除”，餐桌自动恢复空闲。

## v0.6 功能

- 员工可在订单管理中通过“订单日期 + 当日三位编号”办理换桌，例如将当天 `001` 号订单从 `T0001` 换至 `T0008`。
- 换桌时登记实际到店人数；仅当人数超过原桌座位数时允许操作，新桌必须空闲且能够容纳全部顾客。
- 换桌在同一事务中完成：订单绑定到新桌，新桌变为“使用中”，原桌变为“待清理”，避免两名员工同时锁定同一餐桌。
- 已支付订单不能换桌；电话预约生成的订单换桌时会同步更新预约绑定，结账后的押金退款仍关联正确订单。

## v0.5 功能

- 员工可在“电话预约”中登记顾客姓名、电话、人数、预约时间和餐桌。
- 确认预约时必须收取模拟押金，成功后餐桌自动变为“已预订”；不能在餐桌管理中绕过押金直接设置。
- 押金按餐桌容量计算：2 人桌 ¥20、4 人桌 ¥30、6 人桌 ¥40、8 人桌 ¥50，之后按相同规则递增。
- 员工可从预约记录直接载入预约桌和顾客信息并开单。
- 预约账单支付成功后自动模拟退回押金，支付回执显示退款金额与时间；取消未入座预约也会退款并释放餐桌。
- 预约和押金均为本地演示流程，不会发生真实收款或退款。

## v0.4 功能

- 管理员可在运营仪表盘选择月份，总营收和当月订单数随月份更新。
- 菜品销量、销售额、Top 5 与销量冠军均按所选月份计算，仅统计成功支付的订单。
- 独立销售排行页与仪表盘共用所选月份，切换页面时保持月份不变。
- 员工和管理员界面不再显示支付记录入口，仍可在订单页面完成模拟收款。

## v0.3 功能

- 顾客、员工和管理员修改密码时必须输入旧密码，并输入两次一致的新密码；新密码长度为 6–20 位。
- 普通个人资料和账号编辑不接受密码修改，避免绕过旧密码验证。
- 每个营业日的订单编号从 `001` 开始，最多到 `999`；界面以“日期 + 三位编号”区分订单。
- 订单、订单明细和支付记录默认只读取当天，支持按日期范围查询、分页和调整每页数量。
- 订单明细在展开单个订单时加载，避免首次进入页面时读取全部历史明细。

## v0.2 功能

- 保留原有 6 道菜，新增黑椒烤鸡、玛格丽特披萨、番茄海鲜烩饭、南瓜浓汤、草莓芝士蛋糕、芒果酸奶，总计 12 道。
- 每道菜都有本地图片。顾客菜单、购物车、员工菜单和管理员菜品管理均显示图片；管理员可编辑图片地址。
- 顾客提交订单后可立即支付或稍后支付。支持微信 / 支付宝模拟支付，员工和管理员另可模拟现金收款。
- 明确显示模拟支付提示，**不会发起真实扣款或收款**。尚未接入微信或支付宝商户接口；`DEMO_PAYMENTS_ENABLED=false` 可关闭模拟支付。
- 支付状态独立于餐桌状态，记录支付流水、方式、金额、时间。管理员首页收款统计只累计模拟支付成功的流水。
- 服务端按菜品价格计算金额，同一事务创建订单、明细并扣库存；库存不足会整体回滚。
- 支付金额以数据库为准；并发 / 重复支付返回同一流水。已支付订单不能删除，明细不允许直接修改。
- 未支付订单可由员工或管理员删除并退回库存。支付不自动释放餐桌，员工根据实际用餐情况清理、调整餐桌状态。
- 使用服务端登录会话校验支付权限；顾客只能查看自己的订单、明细、流水和个人信息，接口不再返回账号密码。

## 数据库初始化与升级

全新安装：先在 MySQL 执行 `resjk_restaurant.sql`，再启动后端。已有数据库不要重复执行建库脚本。

启动时按顺序执行增量升级。`Version09Upgrade` 为预约增加线上/电话来源并补齐历史记录；`Version08Upgrade` 补充餐桌和菜品，且保留已有餐桌状态、库存、价格和自定义图片地址；`Version07Upgrade` 为预约增加时段结束、到店截止和押金扣除时间，并为历史预约补齐时间；`Version05Upgrade` 新增预约、押金与退款状态表。升级可重复执行并保留订单和支付数据。v0.3 负责订单日期及每日编号，v0.2 负责库存、图片和支付数据。

数据库默认使用 `localhost:3306/resjk`、`root/root`，可以通过 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 环境变量覆盖。服务端默认端口为 8082，可用 `SERVER_PORT` 覆盖；修改后也需同步调整 Vite 代理地址。

本次数据库升级前的本机备份：`.runtime/resjk-before-v0.9.sql`（不提交到 Git）。Git 版本仅保存源码，切换 Git 标签不会自动回滚数据库。

`resjk_seed.sql` 是演示数据重置脚本，会更新已有演示账号、菜单及餐桌数据，不属于正常升级步骤。
